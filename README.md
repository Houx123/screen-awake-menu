# 熄屏不休眠

一个原生 macOS 菜单栏小工具。点击菜单栏的显示器图标会弹出一个紧凑面板，提供“立即熄屏（主机保持运行）”操作，并以一张双指标图展示本机 Codex Token 活动。只关闭显示器；Mac 依靠系统能耗设置保持唤醒，继续等待远程连接。

## 使用

1. 双击 `熄屏不休眠.app`。
2. 点击菜单栏里的显示器图标，打开弹出面板。
3. 点击“立即熄屏（主机保持运行）”只关闭显示器；移动鼠标或按任意键即可重新点亮。
4. 点击“历史数据”打开独立的 App 窗口，查看最近 30 天的每日趋势和明细。
5. 面板中的“关于”显示版本信息，“退出”结束 App。

弹出面板包含：

- **汇总**：可见 24 小时内消耗的 Token 总量，以及当前/最近一小时的速度。
- **每小时用量与速度趋势**：最近 24 个自然小时（含用量为 0 的小时）共用一条时间轴；青色柱表示 Token 用量，橙色平滑曲线表示 tokens/分钟趋势，左右两侧分别显示对应刻度。
- **历史数据窗口**：最近 30 天每日 Token 柱形、平均速度趋势曲线，以及输入、缓存输入、输出、推理输出、总 Token 和记录数明细；窗口关闭后停止历史扫描。

## 图表定义

- **时间窗口**：以本机当前日历和时区为准，显示最近 24 个整点小时（从当前小时的整点往前数 23 小时）。没有记录的小时也会显示为 0。
- **Token 总量**：每条 Codex 用量记录优先使用记录自带的 `total_tokens`。观察到的 `~/.codex` schema 中，`input_tokens` 已包含 `cached_input_tokens`，`output_tokens` 已包含 `reasoning_output_tokens`，因此不会把这些子项再加一遍，保证每个 Token 只计一次。若记录缺少 `total_tokens`，则回退为 `input_tokens + output_tokens`（兼容 `prompt_tokens`/`completion_tokens` 变体）。
- **用量速度**：某一小时的 `tokens / 60`，即把该整点小时内的 Token 总量平均到 60 分钟，单位是 **tokens/分钟**。这是一个按自然小时平均的速率，不是“仅活跃时间”的速率。汇总行优先显示当前小时；当前小时没有用量时，回退到最近一个有用量的小时，并标注该小时。
- **累计计数去重**：`token_usage_record` 与 `event_msg.token_count` 是同一事件的两种记录，解析时只采用其中一类（优先 `token_usage_record`）。当只有累计计数时，转换为相邻事件的非负增量；遇到计数回退（重置、截断或轮转）时以新值作为基线，保证增量非负。

## 数据来源与隐私

- 只读取本机当前用户 `~/.codex` 下的 Token 用量元数据：
  - `~/.codex/sessions/<年>/<月>/<日>/*.jsonl`
  - `~/.codex/archived_sessions/*.jsonl`
- 只提取时间戳与 `input_tokens`、`cached_input_tokens`、`cache_write_input_tokens`、`output_tokens`、`reasoning_output_tokens`、`total_tokens` 等计数字段；**不读取、不显示、不记录**提示词、回复、工具输出等对话内容。
- 全程只读，不修改 `~/.codex`，不写数据库，不联网，不需要任何凭据或账号信息。
- 无云端账单/配额估算，不做历史归档、导出、通知或告警。

## 性能与刷新

- 打开面板时立即刷新一次，面板可见期间每 30 秒刷新一次；关闭面板后停止后台刷新。
- 解析在后台串行队列执行，不阻塞主线程。
- 只发现最近几天的会话目录，并按文件修改时间过滤；每个文件按字节偏移增量读取，未变化的文件不重复解析。文件被截断、轮转或原地改写时会安全地重新读取。

## 重新构建

```sh
./build.sh
```

构建产物位于 `build/熄屏不休眠.app`（要求 macOS 13+）。

## 测试

```sh
./test.sh
```

运行与 `~/.codex` 真实数据无关的确定性测试，覆盖：用量字段解析与去重、累计计数增量与重置、`token_usage_record`/`token_count` 去重、损坏 JSONL、小时分桶、空状态、速度计算、增量读取与截断处理。测试使用内存构造的记录和临时目录。

## 局限

- 仅在当前观察到的 Codex schema（`token_usage_record` / `event_msg.token_count`）上验证；若未来 schema 变化，会尽可能兼容已知字段名，无法识别的记录会被忽略而不会导致崩溃。
- 会话目录按“开始日期”归档，若某个会话在更早的日期目录中持续追加超过数天，可能不会被发现。
- 速度按自然小时平均，活跃时间较短的小时会被平均低估。
